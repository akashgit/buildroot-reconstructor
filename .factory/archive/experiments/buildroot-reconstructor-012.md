# Experiment #012: Elitist Gate with Patience Counter

## Hypothesis

Add elitist gate with patience counter to prevent containerfile regression (issue #32). Restore the best containerfile after 2 consecutive iterations where reward < best_reward, while allowing 1 iteration of exploration below best.

## Result

**KEEP** — score changed from 0.494 to 0.519 (+0.025)

## What Changed

Single file change to `src/buildroot/agent/loop.py` (+18 lines):

- **Patience counter**: Tracks consecutive iterations where `reward < best_reward`
- **Elitist gate**: After 2 consecutive regressions (patience exhausted), restores containerfile from `best_attempt` before the next builder invocation
- **Exploration allowance**: Permits 1 iteration of regression (exploration) before triggering the gate — avoids being too aggressive (the lesson from experiment #010's early termination catastrophe)
- **Zero overhead**: No additional evaluator calls; uses existing reward comparisons

### Design Rationale

This is the direct fix for experiment #010's post-mortem finding. Experiment #010 showed that aggressive termination (`consecutive_no_improvement >= 3`) causes severe regression by killing packages before they explore enough. The patience counter approach is strictly better:

- It does NOT terminate the run — it restores the best state and continues
- It allows 1 iteration of below-best exploration (vs #010's 3-strike termination)
- Packages that need many attempts to break through level boundaries can keep trying from the best checkpoint

### Connection to Experiment #010 Post-Mortem

The #010 post-mortem recommended "Remove early termination entirely, or raise threshold to ≥8" and "Track reward improvement, not just level." This experiment implements a softer variant: instead of terminating, it checkpoints and restores, and it tracks reward (not just level) for the regression counter.
