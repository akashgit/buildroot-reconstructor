- [DO] For Apache Commons projects, use the Apache underscore tag convention: PROJECTNAME_MAJOR_MINOR_PATCH (e.g., BEANUTILS_1_9_4 for commons-beanutils 1.9.4). — Apache Commons repositories on GitHub tag releases with uppercase component names and underscores, not hyphens or dots. Using the wrong tag silently yields an empty or incorrect checkout, causing Maven to fail with 'no POM in this directory'. (helpful=0, harmful=0)
- [DO] Always use the canonical Apache GitHub mirror URL for Apache Commons artifacts: https://github.com/apache/commons-<component>. — The correct source_repo for commons-beanutils is https://github.com/apache/commons-beanutils. Using an incorrect or stale mirror can result in missing tags or an empty working tree. (helpful=0, harmful=0)
- [DONT] Don't treat a 'no POM in this directory' Maven error as a wrong build-system signal — it almost always means the source checkout failed (bad tag or bad repo URL), not that Maven is the wrong tool. — commons-beanutils 1.9.4 is a Maven project. The error_class 'build_tool/wrong_build_system' is misleading here; the build tool is correct but the source was never present because the git tag was invalid. (helpful=0, harmful=0)
- [DONT] Don't infer the git tag by naively concatenating artifact coordinates (e.g., commons-beanutils-1.9.4). Always look up the project-specific tag convention before the first build attempt. — Different Apache projects use different tag styles; assuming a generic pattern wastes an iteration and produces a zero-source build environment. (helpful=0, harmful=0)
- [DO] Set source_repo to 'https://github.com/eclipse/jetty.project' for any org.eclipse.jetty artifact. — Eclipse Jetty (including jetty-server) lives in the eclipse/jetty.project monorepo on GitHub. Without this, the pipeline has no URL to clone from and /build stays empty. (helpful=0, harmful=0)
- [DO] Use git_tag 'jetty-{version}' (e.g. 'jetty-11.0.20') for Eclipse Jetty releases. — The Eclipse Jetty project tags releases with the 'jetty-' prefix. Omitting the prefix or using a bare version string will cause a clone/checkout failure, leaving /build empty. (helpful=0, harmful=0)
- [DO] For a multi-module Maven project, use '-pl <module> -am' to build only the target artifact and its required dependencies. — jetty-server is a submodule inside the jetty.project monorepo. Building only 'jetty-server' with '-am' (also-make) avoids building all sibling modules and reduces build time and failure surface. (helpful=0, harmful=0)
- [DONT] Don't invoke Maven without first confirming that a pom.xml exists in the working directory. — If the source clone failed or was placed in a subdirectory, Maven will immediately abort with 'no POM in this directory'. A missing POM is never a Maven version problem — it is always a repo/checkout problem. (helpful=0, harmful=0)
- [DONT] Don't classify an empty /build directory as a 'wrong_build_system' error — treat it as a repo-agent failure. — The error class 'build_tool/wrong_build_system' is misleading here. Maven is the correct build system for Eclipse Jetty; the actual failure is that no source was checked out. Misclassifying it can send the build_cmd agent on a wild chase when the fix belongs to the repo agent. (helpful=0, harmful=0)
- [DO] Use JDK 17 (Temurin) as the base image for Jetty 11.x builds. — Eclipse Jetty 11 targets the Jakarta EE 9 baseline and requires Java 11+. JDK 17 (LTS, widely tested) is the safest choice and is what the upstream CI uses. (helpful=0, harmful=0)
